# ViralForge — Spécifications

**Version :** 0.2.0 (Hackathon prototype — Firebase edition)
**Date :** 2026-05-08
**Stack :** HTML + Fastify + Firebase Firestore + Firebase Storage + Runway API

---

## 1. Concept & Vision

ViralForge est un outil de génération de contenu vidéo viral alimenté par l'IA. Il permet aux influenceurs et aux équipes marketing de créer en quelques clics des vidéos optimisées pour les réseaux sociaux — hooks, variants A/B, showcases produit — sans conocimientos techniques.

**Tagline :** _"Create scroll-stopping content in seconds, not hours."_

## 4. Features & Interactions

### 4.1 Hooks Generator
- **Input :** text prompt (e.g. "Opening hook for a fashion haul video")
- **Optional :** reference image URL (Runway uses it as starting frame for image-to-video)
- **Output :** N videos (default 3), each ~5s, 720p, gen4.5 model
- **Status flow :** pending → processing → completed / failed
- **On success :** show video URL + download button
- **On error :** show error message inline

### 4.2 A/B Test Generator
- **Input :** one concept text
- **Output :** N video variants (default 5), each with a numbered label
- **Variations :** same core concept, different hooks/cuts generated by Runway
- **On success :** grid of numbered cards

### 4.3 Product Video
- **Input :** product image URL + product name + optional tagline
- **Model :** gen4.5 (image-to-video)
- **Output :** one promo video with the product name burned in as overlay text (optional)

### 4.4 Voiceover Generator
- **Input :** text script (max 500 chars for cost reasons)
- **Model :** eleven_multilingual_v2
- **Output :** audio file MP3, playable inline

### 4.5 Global
- **Credits display :** live balance from Runway API via `GET /api/credits` on page load
- **API key config :** input to set the Runway API key in localStorage (`VIRALFORGE_API_KEY`)
- **Polling :** frontend polls Firestore `viral_jobs/{jobId}` every 3s until status is `completed` or `failed`

## 6. Technical Architecture

### Web — `apps/web/index.html`
- Single HTML file, Tailwind CDN
- Vanilla JS, no framework
- Firebase 9 (CDN modular SDK) for Firestore reads/writes
- Stores API key in `localStorage.VIRALFORGE_API_KEY`
- Polls Firestore documents for job status

### API — `apps/api/src/index.js` (Fastify)
| Endpoint | Method | Description |
|----------|--------|-------------|
| `/api/credits` | GET | Proxy to Runway org API (CORS workaround) |
| `/api/generate/:type` | POST | Create job in Firestore, trigger Runway, return job ID |
| `/api/health` | GET | Health check |

### Worker — `apps/worker/src/index.js`
- Polls Firestore `viral_jobs` where `status == 'pending'`
- Processes jobs sequentially (1 at a time to respect rate limits)
- Calls Runway API server-side (API key from Firestore doc inputData)
- Uploads output to Firebase Storage
- Updates Firestore doc with outputUrl + status

### Firebase Collections

**`viral_jobs`** — one doc per job:
```js
{
  jobId: string,          // e.g. "hook_abc123"
  jobType: string,        // "hooks" | "abtest" | "product-video" | "voiceover"
  status: string,         // "pending" | "processing" | "completed" | "failed"
  inputData: {
    prompt?: string,
    imageUrl?: string,
    concept?: string,
    script?: string,
    productName?: string,
    tagline?: string,
    brandColor?: string,
    count?: number,
    apiKey: string,       // user's Runway API key (never stored long-term)
    userId: string,
  },
  outputUrl?: string,     // Firebase Storage URL once done
  error?: string,
  createdAt: timestamp,
  updatedAt: timestamp,
}
```

### Firebase Storage
- Bucket: `photo-beemm.firebasestorage.app`
- Path pattern: `viralforge/{jobId}.{ext}` (e.g. `viralforge/hook_abc123.mp4`)

### Runway API Key Handling
- User enters their Runway API key in the web UI
- Stored in `localStorage.VIRALFORGE_API_KEY` (client-side only)
- Sent with each job creation request to the API
- API stores it in Firestore `inputData.apiKey` (short-term for processing)
- Worker reads it from Firestore to call Runway server-side
- Never persisted anywhere after job completes

## 7. API Integration

### Runway SDK usage pattern (worker):
```js
const client = new RunwayML({ apiKey: userApiKey });
const task = await client.imageToVideo.create({ model:'gen4.5', promptText, image });
const result = await task.waitForTaskOutput({ timeout: 120000 });
```

### Models used:
| Feature | Model | Cost |
|---------|-------|------|
| Hooks (text-to-video) | gen4.5 | 12 credits/s |
| Hooks (image-to-video) | gen4.5 | 12 credits/s |
| A/B variants | gen4.5 | 12 credits/s |
| Product video | gen4.5 | 12 credits/s |
| Voiceover | eleven_multilingual_v2 | 1 credit / 50 chars |

### Rate limiting:
- gen4.5: 1 concurrent generation, 50 per day per org
- eleven_multilingual_v2: 1 concurrent, 50 per day per org

## 8. Deployment

### Infrastructure (Firebase)
- **Firestore + Storage:** `photo-beemm` Firebase project
- **API server:** any Node.js host (port 3001) or Cloud Functions
- **Worker:** any Node.js host with internet access (port 3002) — or Cloud Functions

### Environment variables for API:
```
FIREBASE_PROJECT_ID=photo-beemm
FIREBASE_STORAGE_BUCKET=photo-beemm.firebasestorage.app
# Optional — master API key fallback if user doesn't provide one:
# RUNWAYML_API_SECRET=your_master_key
```

### Environment variables for Worker:
```
FIREBASE_PROJECT_ID=photo-beemm
FIREBASE_STORAGE_BUCKET=photo-beemm.firebasestorage.app
```

### Worker polling interval: 5 seconds
- Picks up 1 pending job per poll cycle
- Sequential processing to respect Runway rate limits

## 9. User Flows

### Flow 1: Generate hooks from a topic
1. User enters "Opening hook for a cooking recipe Reels"
2. User hits Generate
3. Web → Firestore: creates N job docs (status: pending)
4. Web → API: POST /api/generate/hooks → worker picks up jobs
5. Web polls Firestore each job doc
6. When all completed, shows N video cards with download buttons

### Flow 2: A/B test a concept
1. User enters "Product unboxing for a skincare brand"
2. Selects 5 variants
3. Web creates 5 job docs in Firestore
4. Worker processes all 5 sequentially
5. Web polls until all 5 show in grid

### Flow 3: Product video with voiceover
1. User enters product name + tagline + image URL
2. User hits "Generate Video" then "Generate Voiceover"
3. Both jobs created in Firestore independently
4. Video shows in tab 3, audio shows in tab 4
